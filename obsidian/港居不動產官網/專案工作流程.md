## 🎯 專案背景與脈絡

港居不動產開發有限公司（統編 `96797997`）主營**包租代管**業務。專案目的不只是做一個形象官網，而是把日常業務中反覆手算、手工處理的事情，變成房東與租客都能自己開來用的線上工具：

1. **官網主頁**：把「包租 vs 代管」兩種方案的差異講清楚，並用 ROI 試算器讓房東當場算出預估收益，直接引導填 Lead 表單。
2. **租金換算工具**：包租代管最常見的爭議來源就是「跨月入住的租金怎麼拆」與「10% 代管服務費怎麼算」。工具把三種計算基準（30 日 / 當月實際天數 / 自訂）全部支援，避免口頭解釋不清。
3. **檔案轉換神器**：租賃合約、房源照片、身分文件常需轉檔，外部轉檔網站有隱私疑慮 → 做成**純瀏覽器端本地運算**。
4. **照片水印工具**：巡檢與招租照需要可信的拍攝時間戳記，用 EXIF 讀取＋Canvas 合成解決。

整體技術定位：**純靜態、零後端、零部署成本**，發布在 GitHub Pages。

## 🕳️ 踩坑筆記

- **`gh` CLI 這台電腦沒裝**：`gh auth status` 直接 command not found。GitHub 操作一律用原生 `git`；remote 早已設定完成，不需要（也不要）重建 repo。
- **Google 雲端硬碟上跑 git**：必須設 `git config windows.appendAtomically false`，否則 GDrive 的檔案鎖會造成 git 寫入失敗。已在 2026-07-25 設定完成。
- **GDrive 同步時機**：換電腦開工前一定要確認桌面版同步圖示已打勾，否則會拿到舊版檔案，最慘是造成 git 衝突。
- **`AGENTS.md` 曾是空殼**：初始化前檔案內只有一行 `CLAUDE.md`，任何 Agent 讀了等於沒讀。2026-07-25 已擴寫為完整藍圖。
- **色碼死寫的教訓**：重構前 4 份 CSS 各寫各的海軍藍，深淺不一致。之後任何新頁面**一律先引入 tokens.css**，不要圖快直接寫 hex。

### 🕳️ CSS 與驗證流程的坑（2026-07-26 新增）

- **`@import` 的層疊順序陷阱（本次卡最久的一題）**：每個頁面 CSS 都在檔首 `@import url('css/components.css')`。CSS 規範下，被 import 的規則會被插在**該檔案所有規則之前**。所以 `styles.css` 後面只要再寫一次 `.nav-menu { display: flex }` 或 `.mobile-toggle { display: none }`，就會以「同權重、後出現者勝」蓋掉 `components.css` 裡 `@media` 內的響應式宣告。
  - 症狀：改完 `components.css` 的 `@media`，工具頁生效了，`index.html` 卻沒生效（因為只有 index 載入 styles.css）。
  - 解法：把 `styles.css` / `watermark.css` 裡重複宣告的 `.nav-menu`、`.nav-link`、`.mobile-toggle` 刪掉，只保留頁面專屬微調，並在原處留註解警告後人不要再宣告 `display`。
- **Python `http.server` 不送 no-cache，量測會騙人**：改完 CSS 後重新載入頁面，瀏覽器仍沿用記憶體中的舊 CSS，導致「明明檔案已改好、`fetch()` 讀到的是新內容，但 `getComputedStyle` 還是舊行為」。判斷方法：檢查 `document.styleSheets` 裡 components.css 的 `@media` 規則數是否為 0。
  - 解法：驗證前換一個 port 重啟 preview server（改 `.claude/launch.json` 的 port），新 origin 就拿不到舊快取。
- **本機沒有 Node/npx/lighthouse CLI**：`gh` 也沒裝。所以 Lighthouse 跑不起來，只能用瀏覽器內腳本做等效稽核（量測所有互動元素的 `getBoundingClientRect`、檢查可及名稱與 label 關聯、圖片屬性、canonical、JSON-LD 解析）。正式分數要靠 PageSpeed Insights 線上補。
- **iframe 量測法**：Browser pane 的 `resize_window` 在某些分頁會卡住不生效（`innerWidth` 不變）。改用「在頁面內建立指定寬度的 iframe 載入目標頁」來量測，媒體查詢會依 iframe 寬度生效，結果等價且可一次跑完 4 頁 × 3 斷點。但要注意：外層視窗處於行動裝置模擬時，iframe 寬度會被夾到視窗寬度，必須先把外層設回桌機寬度。
- **GitHub Pages 不吃底線／未發布新頁 → 要有 `.nojekyll`（2026-08-03 踩到）**：GitHub Pages 預設會把 repo 丟進 Jekyll 處理，Jekyll 會忽略以 `_` 開頭的檔案與部分目錄，也可能讓新頁遲遲沒發布。根目錄放一個空的 `.nojekyll` 就能完全停用 Jekyll，靜態站直接原樣發布。**這個檔案不能刪。** 另外新頁補上 canonical 標籤有助於觸發 CDN 快取更新。
- **`.claude/` 被納入版控 → git 直接癱瘓（2026-07-26 踩到）**：`.claude/launch.json`（preview server 設定）被 commit 進分支後，該目錄在本機是系統保護狀態，`ls`／`Test-Path`／`attrib` 全部 Access denied。結果 `git checkout` 與 `git merge` 一律失敗於 `cannot stat '.claude': Permission denied`，連切回分支都做不到，worktree 一度被留在舊版 main 內容上。
  - 嘗試過無效的做法：`git sparse-checkout set --no-cone '/*' '!/.claude/'`（git 仍會去 stat 該路徑）。
  - 有效解法：`git checkout <branch> -- ':(exclude).claude'` 把分支內容帶進當前分支的 worktree＋index，再單一 commit；同時把 `.claude/` 寫進 `.gitignore` 永久排除。
  - 教訓：**工具鏈的本機設定檔（`.claude/`、`.vscode/` 之類）不要進版控**，收工技能本來就有這條規則，這次是它被 commit 進去才炸的。
- **量測誤判：核取方塊 22×22px 不算違規**：`<input type="checkbox">` 本體只有 22px，但外層 `<label>` 已有 `min-height: 44px` 且包住文字，點 label 就會切換 checkbox → 有效觸控目標其實是整個 label（>44px）。腳本只量 input 本身會誤報。

### 🕳️ 全站架構稽核踩到的坑（2026-08-11 新增）

- **同一個元素被兩份 JS 各綁一次事件 → 功能靜默失效**：`index.html` 載入 `script.js` + `js/navigation.js`、`rent-calculator.html` 載入 `script.js` + `js/layout.js`，兩邊都對 `#mobileToggle` 做 `classList.toggle('active')`。一次點擊觸發兩個 handler，切換兩下正好回到原狀 → **手機漢堡選單點了完全沒反應，且沒有任何錯誤訊息**。
  - 為什麼一直沒被發現：桌機看不到漢堡鈕；手機上點了沒反應容易被當成「還沒載入好」。
  - 教訓：**把共用邏輯抽進模組時，要回頭把舊檔案裡的同名邏輯刪乾淨**，否則就是兩份都在跑。抽 `layout.js`／`navigation.js` 時只做了「新增」沒做「移除」。
  - 檢測法：`getEventListeners($0)`（DevTools）或直接搜尋所有載入的 JS 有幾處 `getElementById('mobileToggle')`。
- **`getElementById` 抓錯 id + 防禦性 `if` 判斷 = 整段功能人間蒸發**：`photo-time-location.js` 寫 `const dropzone = document.getElementById('dropzone')`，但 HTML 上該元素的 id 是 `empty-canvas-notice`。取到 `null` 後，外層的 `if (dropzone && fileInput) { ... }` 把**點擊、拖放、以及 `fileInput` 的 change 監聽**全部一起跳過 → 這頁根本無法上傳照片，卻**零 console 錯誤**。
  - `if (a && b)` 這種防禦性判斷會把 bug 從「大聲的 TypeError」變成「安靜的功能消失」，反而更難抓。
  - **通用檢測法（本次靠這招一次掃出全站問題）**：抓每支 JS 的 `getElementById('X')` 與 `querySelector('#X')`，逐一比對對應 HTML 是否存在該 id。一次跑完 8 頁就找出這條與下面的 `#propertyModal`。
  - 注意誤報：`getElementById(\`basis${...}\`)` 這種模板字串是動態的；註解裡提到的 id 也會被正則掃到。
- **共用 `script.js` 被工具頁載入 → 對不存在的元素掛事件**：`script.js:141` 的 `modal.addEventListener(...)` 沒判空（上一行的 `modalClose` 反而有判），`rent-calculator.html` 沒有 `#propertyModal` → 拋未捕捉 TypeError，**該檔在這一行之後的所有初始化全部中止**。
- **CSS 變數打錯名字不會報錯，只會靜靜退回初始值**：`watermark.css` 引用 `var(--text-main)` **共 11 次，而這個變數從未定義**。CSS 不會警告，`color` 直接退回初始值黑色 `#000`，落在 `#0B132B` 深藍底上（亮度差 19）。
  - 同一頁還有第二層問題：它是常駐深色 UI，卻用了 tokens.css 的**淺色模式** `--text-secondary`（`#334155`）→ 深藍導覽列上亮度差只有 31。
  - 檢測法：`getComputedStyle(el).getPropertyValue('--x')` 回空字串就是沒定義。
- **`data-theme` 掛在 `<html>` 但選擇器寫 `body`**：`initThemeSwitcher()` 設的是 `document.documentElement`，components.css 卻寫 `body:not([data-theme="dark"]) .icon-moon { display: inline-block }`。`body` 永遠沒有這個屬性 → 該選擇器**恆成立**，且與 `[data-theme="dark"] .icon-moon { display: none }` 同權重（皆 0,1,0）、排序在後者之後 → 後者永遠勝出，**主題鈕永遠顯示月亮**。改用 `:root:not(...)` 對齊實際掛載位置。
- **深色模式漏網頁面：CSS 根本沒有 `body` 規則**：`image-converter.css`／`photo-time-location.css`／`id-card-watermark.css` 三份都沒寫 `body { }`。淺色模式下靠瀏覽器預設白底黑字勉強能看，一切深色就變成 `--text-dark`（近白 `#F8FAFC`）壓在白底上，完全讀不到。已在 `components.css` 的 `body` 補上 `background-color: var(--bg-light); color: var(--text-dark)`。
- **無頭瀏覽器不合成畫面 → CSS transition 永遠卡在起始值**：Browser pane 未顯示時頁面不 render，`transition` 不會推進（`getAnimations()` 顯示全部 `running` 但永遠不完成）。於是 hover／click 下拉選單後 `getComputedStyle` 讀到的仍是 `visibility: hidden; opacity: 0`，**會誤判成功能壞掉**。
  - 解法：驗證互動前先注入 `*,*::before,*::after{transition:none!important;animation:none!important}`，讓計算值直接跳到終值。本次差點因此誤修一個沒壞的下拉選單。
- **對比度腳本要處理漸層與 alpha 疊色**：`.btn-gold`／`.region-chip.active` 的底色是 `background-image: linear-gradient(...)`，`getComputedStyle().backgroundColor` 讀到 `rgba(0,0,0,0)`。若只沿祖先鏈找第一個非透明 `backgroundColor`，會誤判成「深色字壓深色底」（實際是深色字壓金色漸層，完全正常）。`.tab-btn` 的 `rgba(197,160,89,0.1)` 半透明底也要跟下層合成才算得準。
- **`@import` 進來的 CSS 也吃瀏覽器快取**：改 `components.css` 後即使對 HTML 加 `?v=timestamp`，`@import url('components.css')` 仍走記憶體快取。症狀是 `fetch('/css/components.css')` 讀到新內容、`getComputedStyle` 卻是舊行為。唯一可靠解法還是**換 port 重啟**（本次換了 9 次）。
