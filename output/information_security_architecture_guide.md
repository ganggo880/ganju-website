## 1. 資訊安全基石：CIA 三要素

資訊安全的所有技術、規範與架構設計，本質上都是為了守護 **CIA 三要素**。

```
              【 機密性 Confidentiality 】
                    /             \
                   /   資訊安全    \
                  /     鐵三角      \
                 /                   \
   【 完整性 Integrity 】 ───── 【 可用性 Availability 】
```

### 1.1 機密性 (Confidentiality)
* **核心定義**：確保只有**獲得授權的實體（人、系統、進程）**才能讀取或存取資訊，嚴防未授權的洩漏與窺探。
* **生活化比喻**：租賃合約中的身分證影本與銀行存摺，鎖在專用防保險箱內，只有經理人有鑰匙能開。
* **關鍵實踐技術**：
  * 傳輸加密（TLS 1.3 / HTTPS）與靜態資料加密（AES-256 GCM）。
  * 存取控制（基於角色的權限控制 RBAC、基於屬性的權限控制 ABAC）。
  * 資料遮蔽（Masking / Redaction）與去識別化（Tokenization）。
  * 瀏覽器端純本地運算（Zero-Knowledge Client-Side Processing）。

### 1.2 完整性 (Integrity)
* **核心定義**：確保資訊與系統在產生、傳輸、儲存與處理的全生命週期中，**保持真實、準確、完整且未被擅自竄改或偽造**。
* **生活化比喻**：租約上的租金金額、起租日期一旦雙方用印簽署，任何人都不能私自塗改或抽換內頁。
* **關鍵實踐技術**：
  * 加密雜湊校驗（SHA-256 / SHA-3）。
  * 數位簽章（Digital Signatures）與非對稱金鑰認證（RSA / ECDSA）。
  * 區塊鏈或不可竄改稽核日誌（Append-Only Audit Logs）。
  * 資料庫交易一致性（ACID）與資料校驗約束（Constraints）。

### 1.3 可用性 (Availability)
* **核心定義**：確保**獲授權的實體在需要時，隨時能夠及時、可靠地存取系統、服務與資料**。
* **生活化比喻**：房客或房東隨時點開線上租金試算器或合約管理系統，系統都能在 1 秒內順暢回應，不會當機或斷線。
* **關鍵實踐技術**：
  * 高可用性架構（High Availability, HA）與負載平衡（Load Balancing）。
  * 內容傳遞網路（CDN）與分散式阻斷服務（DDoS）清洗防護。
  * 異地備份、容災復原演練（RTO / RPO 目標管理）。
  * 無伺服器純靜態託管（GitHub Pages / S3 + CloudFront）。

## 2. 系統威脅分析：STRIDE 威脅建模框架

STRIDE 是微軟（Microsoft）提出的成熟威脅分析模型。它從**攻擊者目標**出發，將所有潛在的安全威脅歸納為 6 大類，並精準對應防禦手段。

```
 ┌─────────────────────────────────────────────────────────────┐
 │                    S - Spoofing (身分冒充)                   │
 │                    T - Tampering (資料竄改)                  │
 │                    R - Repudiation (否認行為)                │
 │                    I - Information Disclosure (資訊洩漏)     │
 │                    D - Denial of Service (阻斷服務)          │
 │                    E - Elevation of Privilege (權限提升)     │
 └─────────────────────────────────────────────────────────────┘
```

| STRIDE 維度 | 威脅定義與攻擊手法 | 破壞的 CIA 屬性 | 核心防禦對策 (Security Controls) |
|---|---|---|---|
| **S** - Spoofing<br>（冒充身分） | 攻擊者偽裝成合法使用者、管理員或伺服器（如偽造 Cookie、假冒 DNS、釣魚登入）。 | 驗證 (Authentication) | • 多因素驗證 (MFA / FIDO2)<br>• 強身分驗證協定 (OpenID Connect / OAuth2)<br>• 數位憑證與 SPF/DKIM/DMARC 郵件驗證 |
| **T** - Tampering<br>（資料竄改） | 惡意修改傳輸中或資料庫內的資料（如中途竄改租金金額、SQL Injection 竄改表格、中間人攻擊 MITM）。 | 完整性 (Integrity) | • 全站強制 HTTPS / TLS 1.3<br>• HMAC 訊息鑑別碼與雜湊驗證<br>• 參數化查詢 (Prepared Statements)<br>• 唯讀檔案系統與程式碼完整性簽章 |
| **R** - Repudiation<br>（否認行為） | 使用者或攻擊者執行某項操作後，否認該行為（如房東否認承諾修繕、房客否認收受通知且無紀錄）。 | 不可否認性 (Non-Repudiation) | • 集中式防竄改審計日誌 (Audit Logging)<br>• 數位簽章與時間戳記憑證 (Timestamping)<br>• SIEM 安全資訊與事件集中管理 |
| **I** - Information Disclosure<br>（資訊洩漏） | 機密敏感資料暴露給無權限者（如身分證未遮蔽外洩、原始碼中洩漏 API Key、錯誤訊息印出連線字串）。 | 機密性 (Confidentiality) | • 傳輸與靜態資料加密 (End-to-End Encryption)<br>• 最小化個資收集 (Data Minimization)<br>• 敏感設定隔離 (`.env` + 密鑰管理器 Vault)<br>• 客戶端純本地運算（資料不上傳雲端） |
| **D** - Denial of Service<br>（阻斷服務） | 消耗系統資源導致合法使用者無法使用（如 SYN Flood、運算型 DoS、大量並發 API 耗盡記憶體）。 | 可用性 (Availability) | • 速率限制 (Rate Limiting / Throttling)<br>• CDN 邊緣快取與 Cloudflare DDoS 防護<br>• 彈性自動擴展 (Auto-scaling)<br>• 非同步佇列與斷路器模式 (Circuit Breaker) |
| **E** - Elevation of Privilege<br>（權限提升） | 低權限使用者非法取得高權限操作能力（如水平越權 IDOR、垂直越權提權為管理者）。 | 授權 (Authorization) | • 最小權限原則 (Principle of Least Privilege)<br>• 嚴格伺服器端權限驗證 (RBAC / ABAC)<br>• 輸入嚴格驗證與型別轉換 (Input Validation)<br>• 停用預設帳號與高權限隔離 |

## 3. 防護策略：縱深防禦體系 (Defense in Depth)

縱深防禦源自軍事戰略思想——**「絕不把所有安全押注在單一防線」**。即使外圍防線被攻破，內部的各層防護網仍能有效限制損害。

```
                 【 1. 人員與管理政策層 (Policies & Training) 】
             ┌──────────────────────────────────────────────────┐
             │       【 2. 實體安全層 (Physical Security) 】     │
             │   ┌──────────────────────────────────────────┐   │
             │   │    【 3. 邊界與網路層 (Perimeter & Network) 】│   │
             │   │   ┌──────────────────────────────────┐   │   │
             │   │   │   【 4. 主機與計算層 (Compute & OS) 】│   │   │
             │   │   │   ┌──────────────────────────┐   │   │   │
             │   │   │   │ 【 5. 應用程式層 (Application) 】│   │   │
             │   │   │   │   ┌──────────────────┐   │   │   │   │
             │   │   │   │   │【 6. 資料層 Data 】│   │   │   │   │
             │   │   │   │   └──────────────────┘   │   │   │   │
             │   │   │   └──────────────────────────┘   │   │   │
             │   │   └──────────────────────────────────┘   │   │
             │   └──────────────────────────────────────────┘   │
             └──────────────────────────────────────────────────┘
```

### 縱深防禦各層級防護重點：

1. **資料層 (Data Layer)**：最核心的資產。
   * 防護：AES-256 加密、欄位級去識別化、每日定時備份、資料遺失防護 (DLP)。
2. **應用程式層 (Application Layer)**：軟體與 API 入口。
   * 防護：輸入驗證 (XSS/SQLi 防禦)、CSRF Token、Content Security Policy (CSP)、安全 Header。
3. **主機與計算層 (Compute / OS Layer)**：運行伺服器與容器。
   * 防護：最小化基礎映象檔、自動安全性修補 (Patch Management)、端點防護 (EDR)、停用非必要 Ports。
4. **邊界與網路層 (Network / Perimeter Layer)**：傳輸管道與流量閘道。
   * 防護：Web 應用程式防火牆 (WAF)、微隔離 (Micro-segmentation)、虛擬私有雲 (VPC)、零信任網路存取 (ZTNA)。
5. **實體安全層 (Physical Layer)**：機房與硬體設備。
   * 防護：生物辨識門禁、雙重電源備援 (UPS)、監視錄影、硬體安全模組 (HSM)。
6. **人員與管理層 (Personnel & Governance Layer)**：人是最大的漏洞也是最強的防線。
   * 防護：資安意識培訓、社交工程演練、離職即時停權流程、最小特權指派。

## 4. 架構設計原則：現代防禦性架構

在設計軟體系統與雲端架構時，應貫徹以下 **5 大防禦性設計原則**：

### 4.1 零信任架構 (Zero Trust Architecture)
* **三大原則**：
  1. **持續驗證 (Verify Explicitly)**：不因處於內網就給予信任，每次存取皆需身分、裝置、情境驗證。
  2. **最小權限 (Use Least Privileged Access)**：即時給予剛剛好完成任務的權限（JIT / JEA）。
  3. **假設已被入侵 (Assume Breach)**：將攻擊面切割至最小微網段，加密所有流量並全面記錄軌跡。

### 4.2 攻擊面最小化 (Attack Surface Reduction)
* 關閉所有不需要的 API 端點、測試頁面、後台管理端口與未使用的模組依賴。
* **範例（港居不動產官網實踐）**：採用純前端靜態頁面 + 瀏覽器端 WebAssembly 運算，無常駐後端資料庫與伺服器攻擊面，達成實質的「無伺服器、無後端被駭風險」。

### 4.3 故障安全與預設安全 (Fail-Safe Defaults & Secure by Default)
* 系統發生非預期錯誤或中斷時，預設狀態必須是**「拒絕存取」**而非「開放存取」。
* 例如：權限判定邏輯若出現例外拋錯，應立即回傳 `403 Forbidden`，而非放行通過。

### 4.4 職責分離 (Separation of Duties, SoD)
* 關鍵高風險操作（如修改合約、退回押金、金鑰輪替）不得由單一人員獨立完成，需經雙人授權審核（4-Eyes Principle）。

### 4.5 隱私設計 (Privacy by Design)
* 資料生命週期全流程保護：從資料收集（僅收最小必要個資）、使用、儲存到自動銷毀機制。

## 💡 總結心法

> **「安全不是一個功能，而是一個持續演進的架構設計過程。」**  
> 
> 1. 以 **CIA 三要素** 定位核心防護目標；  
> 2. 以 **STRIDE** 系統化盤點攻擊向量與威脅；  
> 3. 以 **縱深防禦** 架構多層次的安全網；  
> 4. 以 **零信任與最小權限** 貫徹防禦性架構設計。
